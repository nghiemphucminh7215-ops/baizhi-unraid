# 百智办公（MonkeyAI）Unraid 社区部署模板

百智办公是一款面向团队的 AI 办公工作台。用户用自然语言描述需求，AI 结合文件、模型和工具执行任务，交付文档、表格、PPT、代码或设计成果，而不只是回答问题。

- 官网：https://work.baizhi.cloud/
- 产品文档：https://work.docs.baizhi.cloud/
- 开源源码：https://github.com/chaitin/MonkeyCode
- 模板反馈：https://github.com/nghiemphucminh7215-ops/baizhi-unraid/issues

> 本仓库为社区适配，不是厂商官方 Unraid 发行版，也不代表 Unraid 已审核或上架。当前仅能进行静态配置和镜像清单检查，尚未在真实 Unraid/Docker 环境启动验证。请先使用独立测试环境，不要连接生产数据库。

## 产品能力

### 办公：从资料到可交付成果
制作 PPT、编写文档、处理表格和整理文件。例如将活动材料整理为汇报演示文稿、分析销售数据并输出报告；可在同一会话中继续补充要求、调整成果。

### 编程：从需求到代码
辅助架构设计、代码编写、现有项目阅读、问题修复和测试。AI 的执行范围受工作环境、工具权限、模型能力及用户授权约束，重要改动仍应审核和验证。

### 设计：从创意到作品
支持海报、平面设计、交互设计及短剧等创作场景，可结合配置的图片和视频生成服务生成素材。具体能力及费用取决于所用模型、资源和服务方案。

### 团队统一管理
共享大模型、知识库、技能、专家、MCP 连接器和规则；按成员或分组配置资源权限，管理积分、额度与资源使用，查看审计记录和团队使用统计。可连接自己的模型服务和业务工具。

### 自主部署与扩展
在自己的基础设施中管理数据、备份、升级和访问权限。源码采用 AGPL-3.0；修改、使用与分发需遵守相应许可证。使用外部模型或工具时，相关内容仍可能发送至对应服务，私有化部署不等于所有数据都不出网，也不等于内置本地大模型。

## 版本、客户端与授权

官网公布免费方案最多 10 个团队席位；付费方案的席位、云电脑、技术支持和内置内容以官方购买方案为准。当前桌面客户端包括 Windows、macOS 和 Linux x64，可连接自建服务器。Android、iOS、Linux ARM 和鸿蒙等平台的原生客户端仍标注“敬请期待”，不要视为已经可用。

本模板引用官方服务器发布包 v26111301 的预构建镜像。**源码许可证与镜像/商业发行版授权是不同事项**：官方发布包文档注明私有 Backend 可初始化管理员，但新增其他成员可能需要导入有效 License。请在部署前向官方确认免费版获取方式、镜像使用条款与席位授权；本模板不提供、签发或绕过产品 License。

## 部署结构与要求

这是五个服务组成的应用，不能仅启动后台页面容器：

| 服务 | 用途 |
| --- | --- |
| db | PostgreSQL 18.6，持久化业务数据 |
| rustfs | RustFS 对象存储，保存技能包等资源 |
| migrate | 与 Backend 同版本的一次性数据库迁移 |
| backend | API、模型与工具代理、团队资源及远程执行中转 |
| admin | 管理后台及 HTTP 入口 |

另有一次性 permissions 服务，仅初始化本项目命名卷根目录的 UID/GID 和权限，不挂载宿主机目录或 Docker socket，不访问网络。只有管理入口映射到宿主机；数据库、后端和对象存储不直接暴露端口。

Unraid 原生 Compose 安装需使用支持该功能的版本（面向 Unraid 8 Compose 合约）；旧版单容器安装器不适用。若使用自行安装的 Compose 工具，请确认支持 Compose V2 的 depends_on 完成/健康条件。官网标示服务器可从 1 核 CPU、1 GB 内存起步，实际需求取决于团队规模、资源存储和任务负载；模型推理所需算力不包含在此配置内。

## 手动 Compose 安装

1. 将本仓库下载到 Unraid 持久存储的独立目录，不要放在重启即清空的目录。进入 baizhi 目录，将仓库根目录的 .env.example 复制到此目录并命名为 .env，将权限设为 0600。
2. 设置 NAS 内网绑定 IP、服务器对外 URL、管理员邮箱，以及三个相互独立的随机密钥（数据库密码、对象存储密钥、初始管理员密码）。示例文件没有通用默认密码；数据库、对象存储密钥和访问地址等必填项缺失时 Compose 会拒绝启动。首次管理员密码必须另行填写，空值不能视为已完成账户初始化。可在可信终端用 openssl rand -hex 32 生成随机值；不要将真实 .env 上传 GitHub。
3. 在该目录运行 docker compose config --quiet 检查配置，再运行 docker compose pull 和 docker compose up -d。命令应在 Unraid 或隔离测试机上执行，本仓库生成过程中没有在用户设备上部署服务。
4. 确认迁移成功且 backend、admin 的健康检查通过，再打开所配置的对外地址。需要时查看 docker compose ps 及 docker compose logs --tail=100；日志可能包含业务内容，分享前请脱敏。
5. 首次登录后修改管理员密码，并从 .env/安装器配置中移除初始化密码，再重建 backend。初始化只在空用户库时执行，不会用环境变量重置已有账号。
6. 在管理后台配置所需模型、资源、权限和产品 License；下载官方桌面客户端并连接此服务器。

默认内部入口为 HTTP、宿主机端口 8088（可改），默认示例仅绑定 127.0.0.1。直接从局域网访问时应显式绑定 NAS 的内网 IP，并同步修改 MONKEYAI_PUBLIC_URL。**不要将明文 HTTP 直接暴露公网**；生产环境应配置可信 HTTPS 反向代理、身份认证和防火墙。若使用反向代理，仅将实际代理地址加入 MONKEYAI_TRUSTED_PROXY_CIDRS，不要信任所有网段。本模板禁用共享证书和自动签发，不包含任何私钥。

## 持久化、备份与升级

数据位于本 Compose 项目的 Docker 命名卷：PostgreSQL、RustFS 数据/日志、运行身份、产品 License、上传临时目录和管理入口证书状态。默认 Docker 数据根目录由 Unraid 管理；请确认 Docker 存储本身持久化并有足够空间。

备份应一致地保存 PostgreSQL 数据库与该快照引用的对象存储文件，同时保存 runtime 中的远程执行签名身份、license 中的机器标识和授权文件，以及受限访问的 .env。数据库卷应使用 PostgreSQL 备份工具或停机一致性备份，不能在写入期间随意复制文件。

升级前备份并阅读官方说明；admin、backend、migrate 必须使用同一发布版本。不要自动切换数据库大版本，也不要将全新迁移历史强行应用到旧库。普通 docker compose down 保留命名卷；**docker compose down -v 会删除数据卷，禁止作为常规升级/排错步骤**。本模板不自动删除或重建已有数据。
